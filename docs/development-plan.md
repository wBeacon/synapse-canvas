# Synapse Canvas 开发规划

更新日期：2026-10-25。本文件统一维护适配目标、当前状态、技术边界和后续验收项，不另存阶段记录或咨询草稿。

## 目标与范围

将继承自 [dsh-synapse](https://github.com/liangmianya/dsh-synapse) 的可视化对话工作台逐步扩展为多 Harness 项目。先用 WorkBuddy、CodeBuddy 的实际行为确定适配边界，再提取经过验证的公共能力。

保留上游 Git 历史、署名与 MIT 许可。DSH 原有功能继续回归验证；不提前承诺各平台具有相同的会话接口、分叉能力或 UI 扩展方式。

## 当前状态

| 模块 | 状态 | 已确认的边界 |
| --- | --- | --- |
| DSH | 保留原有运行路径，已提取事件适配器 | 存储和旧前端尚未整体迁移到公共层 |
| 公共会话模型 | 已实现首版 | 会话、轮次、工具归属、消息修订及线性布局；原生 ID 与锚点保持不透明 |
| WorkBuddy 本地历史 | 已实现受限只读接入 | macOS WorkBuddy 5.9.2 企业版客户端的本地开发任务；使用当前版本的本地存储格式 |
| 本地浏览器地图 | 已实现 | 会话 / 工作区筛选、搜索、拖拽、缩放、详情和已保存记录刷新；位置仅保存在页面内存 |
| WorkBuddy 对话内 MCP App | 已实测 | 原生任务内显示与交互；可将问答引用发送到承载画布的当前任务 |
| WorkBuddy 常驻画布 | 尚未实现 | 无独立导航、跨任务保持或启动恢复的成功验证；账号只有普通客户端权限 |
| Buddy 菜单网页包 | 已准备候选验证包 | 仅含合成数据，尚未注册到宿主，也不读取真实历史 |
| CodeBuddy | 尚未接入 | 需分别确定目标形态与实际能力，不能照搬 WorkBuddy 结论 |
| 指定源会话追问与原生分叉 | 尚未验证 | WorkBuddy 源会话能力保持 `send: false`、`fork: false` |

对话内 MCP App 与应用级常驻是不同的验收目标。连接器配置可持续存在，不能证明画布拥有常驻入口或保活能力。

## 架构与职责

```text
core/conversation.js        公共事件 → 会话轮次 → 地图布局
core/read-only-payload.js   短正文列表与按需详情

adapters/dsh.js        → index.js / DSH 原有存储与宿主
adapters/workbuddy.js  → preview/server.js → preview/app.js ┐
                      → mcp/server.js     → mcp/app.js     ├→ preview/view.js
buddy/demo.js                             → buddy/app.js  ┘
```

- 平台适配器负责原生索引、日志、消息块与上下文信封转换。公共视图不直接读取数据库或解释平台日志。
- 公共层按原生消息 ID 处理后续修订，按 callId 将工具结果归回所属轮次。DSH 的序号和 WorkBuddy 的消息 ID 不互换。
- 当前地图只连接同一会话的相邻轮次；跨会话继承和原生分叉必须有经过验证的关系与锚点。
- 宿主交互与源会话能力分开：发送引用到当前任务，不等于向所选源会话追问，更不等于原生分叉。
- HTTP 预览、MCP App 与合成网页包复用同一画布，不复制多套前端。DSH 旧前端后续按实际需求逐步迁移。

## 开发顺序与验收

### 1. 巩固只读基础

已有实现继续保留，新增兼容性工作以可复现样本驱动。

- 补充历史格式变化、消息修订、继承、工具失败和异常日志的兼容性样本。
- 排除已删除、已知归档或隐藏、其他账号及不支持来源；遇到未知格式明确提示。
- 不将系统上下文、推理正文、工具参数或工具结果正文误作问答展示。
- 验收：合成测试覆盖投影与读取边界；真实测试任务的轮次和正文可核对；DSH 回归通过。

### 2. 优先验证 WorkBuddy 常驻入口

当前依赖是获得适用于实际账号的接入契约。普通客户端「更多 → 自定义菜单栏」本次只能整理已有入口，未发现新增第三方网页的入口。现有公开插件组件也不足以证明支持独立导航页面。

候选路径：

| 路径 | 已有依据 | 下一项依赖 |
| --- | --- | --- |
| 企业自建菜单 | 官方支持通过 HTTPS iframe 将 Web 页面加入导航 | 企业后台配置权限、受控托管与明确测试范围；当前不具备 |
| Buddy 应用网页菜单 | 官方文档索引与可下载示例包含网页 ZIP、`pages` 清单及侧栏菜单 | 可配置的测试应用与预览入口；直接访问文档与索引曾存在版本差异，以实际后台为准 |
| UI Extension | 本机内置模块存在页面入口、`keepAlive` 和签名分发实现 | 第三方 SDK、本地开发加载、签名与分发契约；静态代码存在不代表第三方可用 |

向官方确认：普通账号是否可安装独立 UI；个人开发者可用范围；最小配置和预览版本；页面生命周期；经用户选择授权的本地开发任务历史 API。尚未联系官方，未修改内部扩展注册信息或签名校验。

现有 `buddy:package` 命令用于构建合成数据的最小网页包。取得支持的入口后，先验证页面承载，再设计真实历史通道；不把私有本地预览改成可被任意外部页面读取的接口。

验收必须分别完成：

1. 点击固定入口直接打开画布，无需发送提示词或调用模型。
2. 关闭原工具消息所在任务后，入口仍可用。
3. 切换任务再返回，检查视角和卡片位置是否保留，区分宿主保活与重新挂载。
4. 重启客户端后入口恢复；是否自动打开页面另行确认。
5. 检查窄窗口、主题与页面异常后的恢复。

### 3. 独立验证 CodeBuddy

WorkBuddy 常驻入口的权限限制不应阻塞独立的 CodeBuddy 能力调查。

- 先确定具体目标：CLI、IDE 或编辑器插件；每种形态分别建立能力矩阵。
- 先验证只读历史和最小画布承载，再测试会话定位、发送与分叉。
- 复用公共模型与视图，新增平台适配器；不复用未经验证的 WorkBuddy 私有字段或协议。
- 验收：能用专用测试任务完成历史投影，并说明该形态支持的 UI 生命周期与权限范围。

### 4. 验证原生写操作与分叉

按平台逐项启用能力，避免由界面操作成功推断第三方接口可用。

- 指定源会话发送：核对目标会话、上下文、回复归属、取消、失败与重复提交行为。
- 分叉：核对精确回答锚点、继承边界、父子关系及原会话是否保持不变。
- 草稿回填：单独验证。当前 WorkBuddy MCP 链路中 `fill` 元信息仍导致直接发送，因此不提供「仅回填」承诺。
- 验收：新增内容只进入目标测试会话；只有经过验证的适配器才开启对应能力。

### 5. 完善公共边界与发布

- 依据至少两个真实适配器的共性继续抽取接口，避免提前制造通用运行时。
- 逐步统一布局持久化、主题与生命周期管理；保持平台专属行为可表达。
- 为每种宿主提供正确的安装配置和能力说明；候选网页包不能冒充已完成的常驻插件。
- 独立发布前更换继承的 npm 包名与元信息，确定版本、构建和安装流程，审查依赖许可及来源说明。
- 验收：构建、测试和打包检查通过；新环境可按 README 安装；不包含凭证、历史数据、生成包或临时文件。

## 数据与运行边界

- WorkBuddy 读取必须显式指定 `--marker` 或 `--account`。标记模式可能扫描多份本地记录定位标记；只返回最终匹配的有效会话。跨账号匹配有歧义时拒绝读取。
- SQLite 只读打开，只读取有效索引对应的本地 JSONL；每份历史暂限 32 MiB，未完成尾行忽略，未知记录提示。账号、归档与来源判断依赖已识别的当前版本字段。
- 列表正文最多 2,000 字符，按需详情最多 200,000 字符。公共模型仅驻留内存，不新增历史数据库。
- HTTP 服务只监听本机回环地址，数据接口校验令牌、Host 和来源，仅接受 GET。完整访问链接和 sessionStorage 令牌不提交仓库。
- MCP 服务通过 stdio 工作，启动时固定会话集合，工具参数不能扩大范围；后续有效记录变化仍会刷新。界面包自包含，保留项目与依赖许可。
- MCP 工具结果只返回计数，正文由资源接口提供；模型若主动读取同范围资源仍可能取得正文，不将此机制描述为模型隔离。
- 引用操作由用户明确点击触发，并标明会发送新消息和触发回复。问题 / 回复最多引用 4,000 / 8,000 字符；截断明确标注。
- 合成网页包不连接真实历史，不调用发送接口，也不包含用户配置。它与 MCP App 使用不同的宿主数据通道。

## 维护与验证

使用 README 中的构建与测试命令。测试使用临时合成数据库、日志和页面资源，覆盖原有 DSH 行为、公共模型、只读范围、HTTP / MCP 边界和网页包资产闭包。

仓库只保留这一份衍生项目开发规划，README 承担安装入口说明；上游原有稳定指南保留。阶段截图、一次性探针、沟通草稿、私有样本及生成产物不纳入开发提交。
