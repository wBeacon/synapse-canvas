# WorkBuddy 只读地图

首版原型已使用 macOS WorkBuddy 5.9.2 企业版的真实测试会话验证。
它在独立的本地浏览器页面显示历史，尚未作为 WorkBuddy 内嵌插件提供。

## 启动

需要 Node.js `>= 22.19.0`，使用 Node 内置 SQLite，无须额外安装依赖。

```sh
npm run preview:workbuddy -- --marker SYNAPSE_CANVAS_PROBE_20261025
```

`--marker` 在用户真实问题中匹配文字，只展示包含该标记的有效本地会话。
如果没有先前的测试任务，可以在 WorkBuddy 中创建一个问题带自定义标记的任务，再用同一个标记启动。

在终端打开打印的完整链接。链接中的随机访问令牌用于授权当前本地预览，不应发布到仓库；页面加载后会从地址栏移除令牌。重新启动服务后应使用新链接。
按 `Ctrl+C` 结束服务。

其他参数：

```sh
# 明确指定索引中 user_id 对应的账号；请先核对它属于当前使用的账号。
npm run preview:workbuddy -- --account '<本地账号ID>'

# 使用自定义 WorkBuddy 数据目录与端口；0 表示由系统分配空闲端口。
npm run preview:workbuddy -- --home /path/to/workbuddy --marker MY_TEST --port 0
```

必须指定 `--marker` 或 `--account`，不会自动展示所有账号。两者可同时使用。
如果同一个标记匹配多个账号，读取会失败，需要再指定账号。

## 已支持

- 按工作区筛选、按标题或问题预览搜索会话；选择会话后查看其各轮问答。
- 每轮一张卡片，按同一会话的顺序连接，显示保存下来的助手回复和工具数量。
- 拖动卡片标题调整位置，拖动背景平移；滚轮平移，按住 Ctrl / Command 滚轮缩放，也可使用缩放按钮。
- “定位”将当前卡片放入视野。“查看详情”按需读取更完整的问答、工具名称和状态。
- 每两秒读取一次已落盘的变化，保留当前视角与卡片位置。拖拽中暂停刷新。

拖动位置仅保存在当前页面内存中；重新加载页面会恢复自动布局。
问题和回复目前按纯文本显示，工具过程仅提供名称和状态。

## 读取与筛选边界

- 以 SQLite 只读模式打开 `workbuddy.db`，读取 `sessions` 索引；只读取与有效索引对应的 `projects/*/*.jsonl` 文件。
- 排除其他指定账号、已删除记录、已知的归档或隐藏状态、云端记录、后台自动化和已知助理来源。
- 标记模式可能需要检查多份本地历史以定位标记；只有最终匹配的会话会发送到本地页面。
- 对账号使用显式范围，不推断当前登录态。单凭磁盘上有记录，不能证明它属于 WorkBuddy 当前登录账号。
- 归档仅按当前已识别的索引状态筛选；尚未证明覆盖 WorkBuddy 所有归档机制，也未验证云端、助理或跨设备任务。
- 根据 WorkBuddy 的消息来源标记剥离已识别的运行上下文信封；不能可靠识别的信封会跳过并提示，不把系统上下文当作用户问题展示。
- 忽略未完成的 JSONL 尾行，跳过格式不正确的记录并提示。同一个原生消息 ID 的后续版本替换旧版本。
- 显式属于其他会话的继承事件不重复投影；跨会话的原生分叉关系尚未验证，地图不推测这些连线。

本地字段与格式属于 WorkBuddy 当前实现细节。缺少必要数据库字段时停止读取；未知事件会提示，不承诺跨版本完整兼容。
每份历史暂限 32 MiB；地图列表中每条消息最多显示 2,000 字符，详情最多显示 200,000 字符。更大或未支持的内容请在 WorkBuddy 中查看。

## 数据边界

预览服务仅监听 `127.0.0.1`；数据接口需要随机令牌，并校验 Host 和浏览器来源。
接口只接受 GET，响应不缓存；会话内容只在进程和本地页面中使用，不写入仓库、导出文件或 WorkBuddy 存储。
访问令牌保存在该标签页的 sessionStorage 中以支持刷新。工具参数、工具结果正文、推理正文和运行时来源信封不发送到页面。

消息发送、会话创建、归档、原生分叉、原生跳转和 WorkBuddy 内嵌画布均未接入。
